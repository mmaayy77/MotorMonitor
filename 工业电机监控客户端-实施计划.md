# Industrial Motor Monitoring MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Qt 6 desktop client and console simulator that manage 100 independently connected industrial motors, perform rule-based diagnosis, persist complete history, and remain responsive during a four-hour 500-frame/second run.

**Architecture:** A Qt Widgets UI thread owns all views, one communication thread owns every `QTcpSocket`, protocol decoder, request tracker, latest-state cache, and alarm engine, and one storage thread owns the only SQLite connection. The simulator is a separate console executable that listens on one port and binds each accepted connection to the device ID requested during the handshake.

**Tech Stack:** C++17, Qt 6.5+ Widgets/Network/SQL/Test/PrintSupport, QCustomPlot 2.1.1, SQLite, CMake 3.21+, GoogleTest 1.14+, Windows 10/11, Ubuntu 22.04 or 24.04.

## Global Constraints

- One virtual motor equals one independent TCP connection; never multiplex multiple device IDs over one connection.
- Manage all client sockets in one Qt event-loop communication thread; never create one thread per device.
- Receive and decode 100–500 legal frames/second; refresh widgets every 200 ms rather than per frame.
- Persist every legal telemetry record, alarm event, command result, and device event under normal disk conditions; never lose records silently.
- Heartbeat interval is 2 seconds; offline timeout is 5 seconds; reconnect delays are 1, 2, 4, 8, 16, and 30 seconds with a 30-second cap.
- Command responses match a 64-bit `RequestId`; timeout is 3 seconds; state-changing commands are not automatically retried.
- SQLite transactions flush at 200 records or 500 ms, whichever occurs first; queue capacity is 50,000 records and high-water mark is 80%.
- UI, socket, and SQLite objects stay in their owning threads; cross-thread messages contain value types only.
- Windows receives full functional validation; Ubuntu receives build, automated-test, connection, telemetry, diagnosis, alarm, and storage validation.
- MVP excludes accounts, permissions, cloud sync, microservices, message queues, Modbus, serial ports, QML, AI, plugins, and automatic upgrades.
